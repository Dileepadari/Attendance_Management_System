About this register

A Google Sheets workbook is the database. Each class has one workbook, each subject is a tab inside it, and each row below the header is one period of one day. This site is the interface teachers use so nobody has to scroll a spreadsheet on a phone.

It is plain HTML, CSS and JavaScript with no build step and no server. The pages read and write the workbooks through Stein, which puts a REST API in front of a Google Sheet.

Using it

  1. Mark attendance loads the roster for a class and subject. Everyone starts present, so a normal day is a few taps and a save.
  2. Marks are saved as a draft in your browser as you go. Closing the tab by accident does not lose the register.
  3. Filing the same date and period twice asks before it replaces the earlier row, rather than quietly recording the class twice.
  4. Student report totals every subject for one student and lists the dates they missed. Class report ranks a whole class and flags anyone below the requirement. Both export CSV.
  5. Edit sheets opens the workbook when something needs fixing by hand.

Connecting your own sheets

The workbooks this project shipped with in 2022 are no longer reachable, so it runs on generated demo data out of the box. To point it at your own:

  1. Build a workbook per class, one tab per subject, laid out as described on the Edit sheets page.
  2. Connect each workbook at steinhq.com and copy the storage id out of the API URL it gives you.
  3. Put the ids into CLASSES in assets/js/config.js and set PROVIDER to 'stein'.

Full setup notes are in DEVDOC.md.

Where the data actually lives

A note on the sign-in

The sign-in is a shared-device convenience, not a security boundary. The check runs in your browser, so anyone who can open the page can get past it. What actually protects the data is the Google account permissions on the workbooks themselves. Do not put anything confidential behind this login.
